# OrbStack Linux 관측 환경

---

> 개발과 기본 실행은 macOS 에서 하고, Linux 에서만 되는 관측(strace·ss·tc netem·eBPF)은 OrbStack 의 `ubuntu` 머신에서 합니다.

## 왜 Linux 머신이 따로 필요한가

로드맵의 관측 도구 절반이 Linux 전용입니다. macOS 에는 `strace` 가 없고, `dtruss` 는 SIP(System Integrity Protection) 때문에 대부분의 바이너리를 추적하지 못합니다. `ss`·`tc netem`·eBPF 도 Linux 커널 기능이라 macOS 에서는 대체할 방법이 없습니다. 반면 Go 는 `GOOS=linux` 한 줄로 교차 빌드되므로, 코드는 macOS 에서 쓰고 바이너리만 Linux 에서 돌리면 됩니다.

OrbStack 머신은 macOS 홈 디렉토리를 같은 경로로 마운트합니다. 그래서 파일을 복사하지 않고 macOS 에서 빌드한 바이너리를 머신 안에서 곧바로 실행할 수 있습니다.



## 확인된 환경 (2026-09-26)

| 항목 | 값 |
|---|---|
| 머신 | `ubuntu` (arm64, running) |
| 커널 | `7.0.14-orbstack` |
| 설치됨 | `strace`, `tcpdump`, `ss`, `tc` |
| 없음 | `lsof`, `bpftool` — 필요한 Phase 에서 `sudo apt install lsof`, eBPF 는 Phase 15 직전에 확인 |

eBPF 는 OrbStack 커널이 어떤 기능을 켜 두었는지에 달려 있습니다. Phase 15 를 시작하기 전에 `bpftool feature` 로 kprobe·tracepoint·BTF 지원을 먼저 확인합니다.



## 실행 절차

```bash
cd ~/study/gonet-lab
make build-linux                                       # bin/gonet-linux (arm64, 정적 링크)

# 터미널 A — 서버
orb -m ubuntu ./bin/gonet-linux listen 127.0.0.1:8080

# 터미널 B — 클라이언트
orb -m ubuntu ./bin/gonet-linux connect 127.0.0.1:8080

# 터미널 C — 관측
orb -m ubuntu ss -tnp state all '( sport = :8080 or dport = :8080 )'
orb -m ubuntu sudo strace -f -e trace=network,accept4,epoll_ctl,epoll_pwait ./bin/gonet-linux listen 127.0.0.1:8080
orb -m ubuntu sudo tcpdump -i lo -nn 'tcp port 8080'
```

서버와 클라이언트는 같은 머신 안의 loopback 으로 붙입니다. macOS 쪽 클라이언트에서 머신 IP 로 붙일 수도 있지만, 그러면 패킷이 OrbStack 가상 네트워크를 지나므로 Phase 0~1 관측에는 loopback 이 더 단순합니다.
