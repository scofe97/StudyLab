# Phase 0 계획 — Network CLI

---

> `gonet listen` 과 `gonet connect` 두 명령으로, Go 의 `net.Listen`·`Accept`·`Dial` 한 줄 아래에서 OS 가 무엇을 만드는지 관측합니다.

## 무엇을 확인하려는가

`net.Listen("tcp", ":8080")` 은 한 줄이지만 그 아래에서 커널은 소켓을 만들고(`socket`), 주소를 붙이고(`bind`), 접속 대기열을 엽니다(`listen`). 접속이 오면 `accept` 가 새 소켓을 하나 더 돌려줍니다. 이 차이를 모르면 Phase 1 에서 "접속 1,000 개면 FD 가 몇 개인가" 같은 질문에 답할 수 없습니다. Phase 0 의 목표는 코드 한 줄과 OS 자원 하나를 짝지어 보는 것입니다.

```bash
net.Listen → socket() → bind() → listen() → listener FD
Accept     → accept4()                     → 접속마다 새 FD
Dial       → socket() → connect()          → 클라이언트 FD
```



## 구현 범위 (완료)

| 파일 | 내용 |
|---|---|
| `cmd/gonet/main.go` | `listen`·`connect` 분기, SIGINT·SIGTERM 을 `context` 취소로 변환 |
| `internal/tcp/server.go` | `Serve` — Accept 루프, 접속마다 goroutine 으로 echo, 종료 시 listener 와 열린 접속을 닫고 핸들러를 기다림 |
| `internal/tcp/client.go` | `Connect` — stdin 을 보내고 EOF 에서 `CloseWrite`(half-close) 후 서버가 닫을 때까지 읽음 |
| `internal/tcp/tcp_test.go` | loopback 실제 소켓으로 echo, 종료 후 접속 거부, 종료 시 열린 접속 정리 |

Phase 1 몫(multi-client 부하, `ReadDeadline`, 강제 종료 실험)은 넣지 않았습니다. 지금 서버에는 타임아웃이 없어서, 접속만 하고 아무것도 보내지 않는 클라이언트가 핸들러 goroutine 을 영원히 붙잡습니다. 이것이 Phase 1 의 첫 실험 대상입니다.



## 관측 명령

```bash
make build
./bin/gonet listen 127.0.0.1:8080                      # 터미널 A
./bin/gonet connect 127.0.0.1:8080                     # 터미널 B, 한 줄 입력 후 Ctrl-D
lsof -nP -iTCP:8080                                    # 터미널 C (macOS)
sudo tcpdump -i lo0 -nn 'tcp port 8080'                # 3-way handshake 와 FIN 확인
```

2026-09-26 macOS 실행에서 `lsof` 는 한 프로세스 안에 LISTEN 소켓(FD 6)과 accept 된 소켓(FD 7)을 따로 보여 주었고, 클라이언트는 FD 5 를 가졌습니다. syscall 순서는 Linux 에서 `strace` 로 봅니다(절차는 `02-01.orbstack-linux-setup.md`).
