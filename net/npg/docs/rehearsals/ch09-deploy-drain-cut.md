# 배포할 때마다 등록 몇 건이 끊기고 "이미 등록됨"이 뜬다 (J4)

- 장: ch09
- 날짜: 2026-11-01
- 앞 장면과의 연결: J1·J2 에서 손님 쪽 기한을 다뤘다. J4 는 구간이 아니라 프록시를 끌 때의 기한(드레인)이다. 8장부터 있던 `Shutdown` 2초가 그대로였다.

## 신고

> "프록시를 배포할 때마다 장비 등록이 몇 건씩 연결이 끊어지고, 다시 보내면 이미 등록되었다고 합니다."

### 창이 몰래 켠 장애

없다. 등록이 4초 걸리게만 두었다(`post_latency=4s`, 실제 업무 시간 흉내). 학습자가 화면의 정지·시작 버튼으로 배포를 두 번 했다.

## 진단 과정

| 순서 | 본 신호 | 세운 가설 | 남김 / 버림과 이유 |
|---|---|---|---|
| 1 | 백엔드 등록 758, 프록시 201 줄 751, 손님 eof 7 | 백엔드는 끝냈는데 프록시가 먼저 죽어 손님에게 못 전했다 (학습자) | 남김 |
| 2 | 정지 순간 처리 중 등록 약 8건인데 끊긴 건 한 번에 3~4건 | 시작한 지 2초가 넘은 요청만 2초 안에 끝난다. 나머지 절반이 끊긴다 (학습자) | 남김. 드레인이 2초였다 |
| 3 | 화면에 "context canceled" | 프록시가 cancelled 로그를 냈다 (학습자) | 버림. 화면 도구의 착시였다. 정지 버튼으로 끈 프로그램은 exit 0 이어도 Go `exec` 가 그 문구를 돌려준다. 화면이 실제 종료 상태를 보이게 고쳤다 |
| 4 | 끊긴 7건은 접근 로그에 줄이 없고 프록시는 exit 0 | `Shutdown` 이 돌려준 기한 초과를 버렸다 | 남김. 배포 도구는 실패를 볼 길이 없었다 |

드레인 값은 평균이 아니라 가장 긴 요청보다 길어야 한다는 데 학습자가 닿았다. 가장 긴 요청은 업스트림 기한 15초가 상한이다.

## 실행 전 예측

재검사 예측은 ADR 0014 「결과」에 적었다: 배포 때 끊긴 등록 0건.

## 실행

창이 같은 스크립트로 두 바이너리를 돌렸다. 조회 초당 50 + 등록 초당 2(4초 걸림), 20초에 SIGTERM, 2초 뒤 다시 띄움.

## 전후 수치

| 지표 | 고치기 전(드레인 2초) | 고친 뒤(드레인 20초) |
|---|---|---|
| 프록시가 꺼지기까지 | 1.99초 (기한에 잘림) | 3.68초 (처리 중 등록을 다 끝냄) |
| 손님 등록 끊김(eof) | 2 | 0 |
| 백엔드가 만든 장비 vs 손님이 받은 201 | 78 vs 76 | 74 vs 74 |
| 취소 뒤에도 백엔드가 끝낸 일 | 2 | 0 |
| 꺼진 동안 연결 거부(refused) | 등록 8, 조회 208 | 등록 5, 조회 328 |

학습자 실연(화면, 배포 두 번)에서는 백엔드 758 vs 손님 751, eof 7 이었다.

## 포스트모템

- 근본 원인: 드레인 2초가 등록 4초보다 짧았고, 기한을 넘긴 사실을 버려 exit 0 으로 끝났다.
- 제품은 이렇게 한다: nginx `worker_shutdown_timeout` 기본 상한 없음, envoy `--drain-time-s` 600, haproxy `hard-stop-after` 상한 없음, caddy `grace_period` 0 = 끝까지 기다림. 쿠버네티스는 SIGTERM 30초 뒤 강제로 죽인다.
- 조치(ADR 0014 결정 3): 드레인 20초(업스트림 15초 < 20초 < 쿠버네티스 30초). 다 못 끝내면 처리 중 요청 수를 로그에 남기고 exit 1.
- 재발 방지: `TestShutdownTimeoutOrder`(드레인 > 업스트림 기한, < 30초. 드레인을 2초로 되돌리는 고의 결함을 잡음), `TestShutdown`(기한을 넘기면 오류를 돌려줌).
- 남은 것: 꺼진 동안의 `refused` 는 그대로다. 프록시가 하나뿐이라 그렇다. 부하 분산기가 이 서버를 먼저 빼 가게 기다리는 일(caddy `shutdown_delay`)은 다음 후보다. exit 1 경로는 단위 시험으로만 확인했다. 업스트림 기한 15초가 요청을 먼저 끊으므로 지금 장면으로는 드레인 20초를 넘길 수 없다.

## 원문 근거

- Go 1.25.1 `net/http/server.go` L3159-3178: `Shutdown` 은 context 기한이 지나면 `ctx.Err()` 를 돌려준다.
- 제품·쿠버네티스 원문: ADR 0014 「원문 근거」.
