# 장애 리허설 기록

장애 리허설은 결과를 장면마다 파일 하나(`chNN-<장면>.md`)로 남깁니다.

8장부터는 기능 시험 대신 운영자가 실제로 겪는 장애로 장면을 짭니다. 기본값으로 먼저 띄우고, 원인을 숨긴 신고 문장만 본 채 관측 신호를 읽어 진단합니다. 판단(ADR)은 장애를 겪은 뒤에 정하고, 개선한 뒤 같은 장애를 다시 일으켜 전후 수치를 비교합니다. 앞 장면의 조치가 다음 장면의 원인이 되게 이야기로 잇습니다.

## 기록 형식 (8장부터)

```markdown
# <장면 이름>

- 장: chNN
- 날짜: YYYY-MM-DD
- 앞 장면과의 연결: <앞 장면의 어떤 조치가 이 장애를 불렀나, 첫 장면이면 "없음">

## 신고
운영자가 처음 받은 문장과 숫자만 적는다. 원인은 적지 않는다.

## 진단 과정
| 순서 | 본 신호(명령·지표) | 세운 가설 | 남김 / 버림과 이유 |
|---|---|---|---|

## 실행 전 예측
## 실행 (사용자가 친 명령)
## 관찰
## 전후 수치
| 지표 | 개선 전 | 개선 후 |
|---|---|---|

## 포스트모템
- 타임라인
- 근본 원인
- 조치
- 재발 방지

## 원문 근거
실제 사례·문서의 링크와 버전.

## 이어 읽을 노트
```

예측은 실행 전에 적고, 실행 뒤에는 고치지 않습니다. 예측이 빗나간 자리가 학습 대상입니다. 원문 근거를 찾지 못한 장면은 만들지 않습니다.

## 7장까지의 기록

3~6장 기록은 앞선 형식(장면 · 증상 · 실행 전 예측 · 실행 · 관찰 · 해석 · 이어 읽을 노트)을 따릅니다. 고치지 않고 그대로 둡니다.
