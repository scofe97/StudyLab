# 0010. TFTP 서버는 os.Root 로 루트 밖 접근을 막고 일반 파일만 읽기 전용으로 내준다

- 상태: 채택
- 날짜: 2026-10-22
- 장: ch06

## 맥락

TFTP 에는 로그인이 없어서 서버가 내줄 수 있는 범위는 서버 프로세스에 준 권한과 경로 검사가 전부다. 클라이언트가 보내는 파일 이름을 그대로 경로로 열면 `../../etc/passwd` 같은 이름으로 루트 밖 파일이 읽히고(경로 순회), 심볼릭 링크로도 밖을 가리킬 수 있다. 요청 패킷은 에이전트가 만든 것이든 위조된 것이든 신뢰할 수 없는 입력이다. 쓰기 요청(WRQ)을 받으면 누구나 서버 디스크에 파일을 올릴 수 있다.

같은 문제를 푼 규격과 구현(원문 확인).

- RFC 1123 §4.2.3.4: 서버 구현은 허용할 경로 이름을 설정으로 제한해야 한다(SHOULD)
- RFC 7440 §7: TFTP 는 로그인과 접근 제어가 없다. 서버 프로세스에 준 권한을 조심해야 하고, 보통 공개 읽기 권한 파일만 내주도록 둔다
- tftp-hpa (`tftpd/tftpd.c` 소스): `--secure` 는 chroot 와 권한 낮춤, `--jail` 은 `openat2` 로 루트 디렉터리 안에 고정, 둘 다 쓰지 않으면 요청 이름을 검사한다. 쓰기는 `max_upload == 0` 이면 읽기 전용이라 WRQ 에 `EACCESS`("server is readonly")를 돌려준다
- dnsmasq (GitHub 미러 `imp/dnsmasq` `src/tftp.c`, 최신 여부는 확인하지 못했다): 경로에 `"/../"` 문자열이 있으면 거절한다. 문자열 검사뿐이다. WRQ 는 `ERR_ILL`(코드 4)과 "unsupported write request" 로 거절한다
- Go `os.Root` (`go doc os.Root`, Go 1.24+): 루트 아래만 접근하고, 루트 밖을 가리키는 요소가 있으면 오류를 돌려준다. 심볼릭 링크는 따라가되 루트 밖을 가리키거나 절대 경로면 거절한다. 장치 파일, `/proc`, 바인드 마운트는 막지 않는다

`os.Root` 동작은 scratchpad 에서 직접 돌려 확인했다. `a.txt`, `sub/../a.txt`, 루트 안을 가리키는 링크는 열리고, `../outside/…`, `/etc/passwd`, `/a.txt`(절대 경로), 밖을 가리키는 링크는 `path escapes from parent` 로 거절된다. 디렉터리 `sub` 는 열린다.

## 선택지

### A. os.Root 로 열고, 일반 파일만 내준다

- 장점: 이름 해석을 커널 수준에서 하므로 `..` 와 심볼릭 링크 우회를 함께 막는다. 권한이 필요 없고 macOS 와 Linux 에서 같이 쓸 수 있다.
- 단점: 디렉터리와 장치 파일은 열려서 `Stat` 으로 따로 걸러야 한다. 절대 경로(`/a.txt`)를 그대로 거절한다.

### B. filepath.Clean 한 뒤 접두어를 비교한다

- 장점: 코드가 가장 단순하다.
- 단점: 검사한 뒤 여는 사이에 심볼릭 링크로 밖에 닿을 수 있다. dnsmasq 가 문자열 검사만 하는 것과 같은 약점이다.

### C. chroot 나 jail 로 프로세스를 가둔다 (tftp-hpa 식)

- 장점: 가장 강하게 가둔다.
- 단점: root 권한이나 Linux 전용 기능이 필요하고 시험하기 어렵다.

## 결정

A 를 고른다.

- 요청 이름의 앞 `/` 는 떼고 루트 안 상대 이름으로 읽는다. `os.Root` 가 절대 경로를 거절하므로 이 처리가 없으면 `/` 로 시작하는 이름을 보내는 클라이언트가 막힌다. tftp-hpa 의 chroot 모드에서 `/` 가 루트인 것과 같은 해석이다.
- 연 뒤 `Stat` 으로 일반 파일인지 확인하고, 디렉터리와 장치 파일은 거절한다. `os.Root` 가 막지 않는 부분을 메운다.
- 심볼릭 링크는 `os.Root` 의 기본 동작을 따른다. 루트 안을 가리키면 따라가고, 밖을 가리키면 거절한다.
- 쓰기 요청(WRQ)은 받지 않고 ERROR 코드 4(Illegal operation)로 거절한다. 이 서버의 목적은 펌웨어 배포(읽기)이고, 쓰기를 받으려면 인증과 용량 제한이 먼저 필요하다. tftp-hpa 는 코드 2(Access violation)를 쓰지만, 이 서버는 "금지"가 아니라 "지원하지 않음"이라서 dnsmasq 와 같이 코드 4 를 쓴다.
- 클라이언트에게는 일반적인 오류 메시지만 보내고, 탈출 시도의 요청 경로와 오류는 서버 로그에 남긴다. 거절 응답에 어떤 코드를 쓸지는 구현에서 정하고 리허설 T6 로 확인한다.
- 서버는 일반 사용자 권한으로 돌리고, 내줄 파일은 공개 읽기로 둔다(RFC 7440 §7).

## 결과

- 쉬워지는 것: 경로 순회와 심볼릭 링크 탈출을 한 곳에서 막고, 읽기 전용이라 서버 디스크에 파일이 올라올 일이 없다.
- 어려워지는 것: 절대 경로를 보내는 클라이언트를 위해 앞 `/` 를 떼는 규칙을 시험으로 지켜야 한다. 루트 안의 디렉터리 이름 요청은 오류가 난다.
- 학습용으로 단순화한 것(프로덕션이면 더 필요한 것): 업로드 인증과 용량 제한, 파일별 접근 제어(허용 목록), 요청 이름 재작성 규칙(tftp-hpa 의 remap), 요청 속도 제한, 클라이언트 주소별 접근 제한.
- 다시 볼 조건: 쓰기(업로드)가 필요해지거나, `os.Root` 를 쓸 수 없는 플랫폼(Go 1.24 미만, js/plan9)에서 돌려야 할 때.
