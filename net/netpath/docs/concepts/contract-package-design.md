# 계약을 한곳에 두는 패키지 설계
---

## 왜 파일 열 개짜리 프로젝트를 네 폴더로 나누는가

> 지금은 나눌 이유가 없어 보입니다. 이유는 **1국면이 아니라 5국면에 있습니다.**

`direction.md` 가 국면 다섯을 놓았고, 그중 2국면은 결과를 OpenTelemetry 로 내보내고 5국면은 Istio 를 얹었다 뺐다 합니다. 그러려면 **측정하는 코드가 관측 백엔드를 몰라야** 합니다. 나중에 갈라내려 하면 이미 얽혀서 못 갈라냅니다.

그래서 처음부터 갈라 두고, 그 경계를 문서가 아니라 **빌드가 강제**하게 만듭니다.



## 폴더마다 알아도 되는 것이 다릅니다

> 기준은 "무엇을 아는가" 와 "상태를 갖는가" 둘입니다.

| 폴더 | 담는 것 | 상태를 갖나 | 도메인 의미를 아나 |
|---|---|---|---|
| `types/` | 계약 · 상수 | 없음 | 모름 (구조만) |
| `utils/` | 공용 변환 | **없음** | **모름** |
| `probe/` | 측정 로직 | 있음 | **앎** |
| `cmd/` | 플래그 · 출력 | — | 앎 |

`utils/` 의 핵심 제약이 **"상태 없음"** 입니다. `RemainingTimeout(ctx, want)` 은 입력만 보고 답을 내므로 여기 맞습니다. 반면 `tracer` 는 훅이 쌓는 상태를 갖고 "이 단계가 hung 이다" 같은 도메인 판단을 하므로 `probe/` 여야 합니다.

`utils` 라는 이름은 Go 커뮤니티에서 논쟁적입니다 — "역할을 말하지 않는 이름"이라 쓰레기통이 되기 쉽다는 지적이 많습니다. 여기서는 **AGENTS.md 가 "상태 없는 공용 변환"으로 경계를 못박아** 그 위험을 문장으로 막고 있습니다.

### 이 구조는 `portal-tunnel` 에서 왔습니다

`phase1-guide.md` 가 참고 대상으로 지목한 저장소를 받아 보니 폴더가 그대로 대응합니다.

```text
portal-tunnel/              netpath-lab/
  types/      ──────────────→  types/      안정된 계약
  utils/      ──────────────→  utils/      상태 없는 공용 변환
  portal/     ──────────────→  probe/      도메인 코어 (이름만 바꿈)
  cmd/        ──────────────→  cmd/        CLI 진입점
```

우리 `AGENTS.md` 도 그 저장소 것의 번역본입니다. "상태 없는 공용 변환은 `utils/`, 도메인 로직은 그 주인 곁에" 같은 문장이 원문에 그대로 있습니다.



## 의존은 한 방향으로만 흐릅니다

> 이것이 지켜지면 매 단계 빌드가 되고, 깨지면 어디서부터 고쳐야 할지 알 수 없게 됩니다.

```text
cmd/  ──→  probe/  ──→  utils/
  │          │
  └──────────┴──────→  types/     (아무것도 import 하지 않는다)
```

`types/` 가 아무것도 참조하지 않는다는 게 출발점입니다. 그래서 누구나 `types` 를 참조할 수 있고, 순환이 생길 수 없습니다.

여덟 단계를 순서대로 밟을 수 있었던 이유이기도 합니다. 1·2단계가 `types/`, 3단계가 `utils/`, 4~6단계가 `probe/`, 8단계가 `cmd/` 인데 **뒤가 앞을 참조하지 그 반대가 없어서** 중간에 깨진 상태가 안 생깁니다.

### 경계를 빌드가 강제합니다

문서에 적어 둔 약속은 지켜지지 않습니다. 그래서 `make lint` 가 검사합니다.

```text
lint:
	@deps="$$(go list -deps ./probe | grep -E 'k8s\.io|go\.opentelemetry\.io' || true)"; \
	if [ -n "$$deps" ]; then echo "probe 코어에 외부 의존성 유입:"; echo "$$deps"; exit 1; fi
```

`go list -deps` 는 **전이 의존까지** 펼칩니다. `probe/` 가 직접 import 하지 않아도, `utils/` 를 거쳐 Kubernetes 클라이언트가 딸려 들어오면 걸립니다.

누군가 "여기서 Pod 이름만 잠깐 읽으면 되는데" 하고 `k8s.io/client-go` 를 넣는 순간 빌드가 실패합니다. **그게 이 세 줄의 값입니다.**



## 계약을 바꾸는 규칙

> `result-schema.md` 가 정한 한 줄이 이 프로젝트의 호환성 정책 전부입니다.

`result-schema.md` 의 마지막 절이 이렇게 정합니다. 필드 이름과 `error_kind` 값은 함부로 바꾸지 않습니다. **추가는 안전하고, 이름 변경과 삭제는 exporter 를 깨뜨립니다.**

그래서 1국면 중에 `tcp.attempts` 를 더한 것은 안전한 변경이었습니다. 2국면 exporter 가 그 필드를 모르면 그냥 안 읽을 뿐입니다.

반대 방향도 실제로 해 봤습니다. **TLS 단계를 1국면에서 통째로 들어냈습니다.** 계약이 한곳에 모여 있어서 영향 범위를 셀 수 있었습니다.

| | 파일 | 곳 |
|---|---|---|
| 코드 | 6 | 74 |
| 테스트 | 5 | 33 |
| 문서 | 10 | 56 |

**`types/` 만 고치면 나머지가 컴파일 에러로 드러납니다.** `StageTLS` 를 지우자 `probe/classify.go` 와 `types/result_test.go` 가 즉시 깨졌고, 고칠 자리를 컴파일러가 가리켜 줬습니다. 계약이 여러 패키지에 흩어져 있었다면 런타임에야 알았을 것입니다.

그리고 계약이 한곳이라 **되돌리는 길도 적혀 있습니다.** `direction.md` 의 1.5국면 절에 되살릴 자리가 표로 남아 있습니다.

| 더할 것 | 어디에 |
|---|---|
| `tls_*` 오류 5개 | `types/error.go` |
| `StageTLS`, `TLSInfo` | `types/result.go` |
| `TLSHandshakeStart`/`Done` 훅 | `probe/trace.go` |
| x509 에러 분류 | `probe/classify.go` |
| 함수형 옵션 | `utils/http.go` |



## 쓰이지 않는 것은 즉시 뺍니다

> AGENTS.md 의 규칙이 실제로 코드를 줄인 자리가 있습니다.

TLS 를 들어내자 `utils/http.go` 의 옵션이 `WithHTTP1()` 하나만 남았는데, **평문만 재면 HTTP/2 가 협상되지 않아 그것도 효과가 없었습니다.** 옵션이 0개면 함수형 옵션 구조가 빈 껍데기입니다.

```go
// 전
func NewTransport(opts ...TransportOption) *http.Transport

// 후
func NewTransport() *http.Transport
```

"명확한 현재 용도가 없고 실제 경계를 지키지도 않으면 즉시 제거한다" 는 규칙을 따른 결과입니다. 1.5국면에서 TLS 검증 우회와 프로토콜 선택이라는 **정당한 선택지**가 생기면 그때 되살립니다.

`connAttempts` 는 반대 경우입니다. 세기만 하고 `Result` 에 담기지 않아 아무도 못 보는 값이었는데, **빼는 대신 내보내기로** 했습니다. "TCP 12ms 성공"인데 시도가 3회면 앞의 IP 들이 죽어 있었다는 뜻이고, 그 사실은 진단을 바꿉니다. 기준은 언제나 "그 구분이 다른 조치로 이어지는가" 입니다.
