# 5장 노트 보강 후보 (학습 중 누적)

Phase 1(예측→채점, 2026-09-21)에서 학습자가 막히거나 직접 요청한 자리입니다. 반영 전이며, 묶어서 보강 프롬프트 한 장으로 넘깁니다.
대상 노트는 `~/runners-high/write/02_os/book/paw_packet-analysis-wireshark/05-01.주소를 받아 오는 프로토콜.md` 입니다.

1. **[학습자 요청] 치트시트 "`REQUEST` 뒤 응답 없음" 에 도식 흐름** — 서버가 OFFER 한 주소를 장부에 적지 않은 채 두 클라이언트에게 같은 주소를 제안하고, 먼저 온 REQUEST 만 ACK 받는 흐름. 학습자는 "REQUEST 를 보내면 바로 써도 된다"고 예측했고(잘못 알던 인과), 정답 공개 뒤에야 이해했습니다.
2. **[학습자 요청] 네트워크 세그먼트의 정의와 범위 도식** — 05-01 은 "같은 세그먼트"를 §6·치트시트에서 정의 없이 두 번 씁니다. 책 노트 전체에서 이 뜻의 세그먼트는 이 두 줄뿐이고 나머지는 전부 TCP 세그먼트입니다(2026-09-21 전수 확인). 학습자는 TCP 세그먼트로 읽었습니다. 라우터를 경계로 브로드캐스트가 닿는 범위를 그림으로 — 01-01.address-reach.svg 와 겹치는지 먼저 확인.
3. **ACK 가 왜 필요한가** — 노트는 ACK 가 "확정한다"고만 적고, OFFER 가 예약이 아니라는 이유를 적지 않습니다. 1번과 한 묶음.
4. **NAK 미기재** — 학습자 질문 "풀이 소진됐으면 거부를 알려 줘야 하는 것 아닌가". DHCPv4 에는 DHCPNAK(메시지 종류 6)가 있고, DHCPv6 는 REPLY 의 상태 코드(NoAddrsAvail)로 알립니다. 노트 표는 ACK(5)에서 끝나고 치트시트는 "응답 없음"만 적습니다. RFC 2131·8415 원문 대조 후 반영.
5. **DISCOVER 의 출발지 주소 `0.0.0.0`** — 노트에 없습니다. 학습자가 스스로 예측해 맞혔습니다(RFC 2131 대조 후 반영).
6. **REQUEST 의 `yiaddr`** — 노트는 "값이 채워졌으면 제안 이후"라고 적는데 RFC 2131 에서 REQUEST 의 yiaddr 은 다시 0.0.0.0 이고 고른 주소는 옵션 50 에 실립니다. 원문·RFC 대조 후 "진행을 읽는 요령" 문장을 점검.
7. **IPv4 릴레이** — 노트는 DHCPv6 릴레이만 다룹니다. 학습자가 첫 질문에서 "게이트웨이를 거치나"를 물었고 릴레이 개념은 몰랐습니다. 라우터에 서버 주소를 설정해 두고 브로드캐스트를 유니캐스트로 대신 전달한다는 한 문단.
8. **ARP 요청이 MAC 브로드캐스트라는 전제** — §4 끝의 "ARP 로 다시 확인"이 이 전제를 깔고 있는데 학습자에게 없었습니다(1장 결손과 같은 뿌리). 링크 한 줄이면 충분한지 01-01 을 확인.
9. **서버 쪽 ICMP 확인** — 학습자가 "ICMP 로 찔러 본다"고 예측. 실제로는 서버가 OFFER 전에 하는 일이고(RFC 2131) 클라이언트는 ACK 뒤 ARP 입니다. 둘의 분담을 한 문장으로.
10. **용어 대응표를 앞쪽에** — 학습자는 SOLICIT·ADVERTISE·REPLY·rapid commit 이 전부 낯설었고, 찾기·제안·선택·확정 네 역할 이름에 IPv4·IPv6 이름을 나란히 둔 3열 표를 받고서야 읽혔습니다. 핵심 요약의 산문을 표로.

## 05-02 「이름과 요청」 후보 (Phase 1, 2026-09-21)

대상 노트는 같은 폴더의 `05-02.이름과 요청.md` 입니다.

11. **HTTP 트랜잭션 정의** — §4 가 "트랜잭션"을 정의 없이 씁니다. 학습자는 TCP 연결로 읽었습니다. 요청 하나와 응답 하나의 짝이고 연결 하나에 여럿이 실린다는 한 문장.
12. **`http.time` 이 재는 구간 도식** — 학습자는 느린 요청을 SYN·ACK 간격으로 찾는다고 예측했습니다. 연결 수립 왕복(네트워크 지연)과 요청→응답 간격(서버 처리 포함)을 한 타임라인에 나란히. 연결 하나에 트랜잭션이 여럿이면 SYN 은 한 번뿐이라는 것까지.
13. **세그먼트 개수 → 윈도우 튜닝의 연결** — "몇 조각으로 왔는지"는 맞혔지만 그것으로 무엇을 판단하는지는 몰랐습니다. 03장 윈도우 100바이트·2,584 세그먼트 예제로 가는 링크와 한 문장의 인과.
14. **존 전송 정의를 §1 에** — §1 이 "존 전송 같은 작업"을 정의 없이 쓰고, 정의는 §2 의 노트의 읽기(AXFR)에 가서야 나옵니다.
15. **DNS 가 TCP 로 넘어가는 흐름 도식** — 512바이트 초과 → 잘림 → TCP 재질의, EDNS(0) 로 UDP 에 머무는 갈래. 학습자는 이 경우가 있다는 것 자체를 몰랐습니다. 잘림(TC) 플래그는 원서·RFC 대조 후.
16. **CONNECT 터널 시퀀스 도식** — 프록시 정의 한 문장 + 클라이언트→프록시 CONNECT(평문) → 200 → 그 뒤는 TLS 바이트. 학습자는 SNI 로 프록시가 정보를 받는다고 추측했습니다. SNI 와의 구분 한 문장.
17. **"필터에 안 잡힐 때" 분기도** — http 필터 0줄(HTTPS 미복호화·HTTP/2·QUIC), dns 필터 0줄(DoT 853·DoH 443)을 한 결정 흐름으로. 심화 학습의 산문 두 문단을 도식으로.
18. **[노트 내부 모순 — 우선] 05-02 가 "윈도우 100바이트 때문에 세그먼트가 2,584개가 됐던 예제"라고 인과로 적었습니다(§3 본문 179행 부근, 면접 대비 FAQ 283행 부근).** 그런데 03-02 의 노트의 읽기는 두 수를 곧바로 이으면 어긋난다고 적습니다 — 5,242,880바이트를 100바이트씩 나르면 52,428개가 필요한데 원문이 센 것은 2,584개이고, 원문도 100 에서 2,584 를 끌어내지 않습니다. 05-02 의 두 문장을 03-02 와 맞게 고칩니다("같은 지표를 다룬다"는 연결은 남기되 인과 단정은 걷어냄). 2026-09-21 Phase 1 대조에서 AI 가 이 문장을 그대로 옮겼다가 학습자의 "처음 본다"는 되물음으로 03-02 를 확인해 발견했습니다.
19. **CONNECT 뒤에 안 보이는 이유는 터널이 아니라 TLS** — 05-02 §4 가 "그 뒤부터는 터널이라 내용이 안 보입니다"라고 적어, 학습자가 "CONNECT 이후가 전부 암호화면 ClientHello 의 평문은 어떻게 되나"를 물었습니다. 프록시는 바이트를 그대로 넘길 뿐 암호화하지 않고, 터널 안에서 4장의 TLS 핸드셰이크가 그대로(ClientHello·SNI 평문) 지나갑니다. 16번 CONNECT 시퀀스 도식에 이 구간을 함께 그립니다. CONNECT 는 프록시에게 하는 말, SNI 는 서버에게 하는 말이라는 구분도.
20. **DoT·DoH 를 왜 쓰는가** — 05-02 심화 학습은 포트와 "dns 필터로 안 잡힌다"만 적고 목적을 적지 않습니다. 학습자 질문 "언제 쓰는 건가", "UDP 도 마찬가지 아닌가". 평문 DNS 는 UDP·TCP 어느 쪽이든 같은 망에서 질의가 읽히고 응답이 바뀔 수 있다는 것, 전송(UDP·TCP)과 암호화(TLS)는 다른 축이라는 것. RFC 7858(DoT)·RFC 8484(DoH) 원문 대조 후 반영.

## 묶음 A 실습 중 요청 (2026-09-22)

21. **[학습자 요청] IGMP/MLD 스누핑을 실습 편 A5 에 설명** — 옆자리에 멀티캐스트가 왜 오는가(도커 브리지는 스누핑을 안 해 전 포트로 뿌림 + promiscuous). "스누핑이 뭐고 IGMP·MLD 는 무슨 뜻인가"를 물었음. 01-01 §4 igmp-snooping 도식과 링크로 잇고, 스누핑하는 스위치였다면 안 보였을 것이라는 대조까지.
22. **[학습자 요청] 랩 구성·설정·도구 개념을 실습 편에** — dnsmasq 가 무엇인지, .conf 의 dhcp-range·port=0 뜻, udhcpc/dhclient 가 무엇이고 네 단계 로직이 커널이 아니라 클라이언트 프로그램에 있다는 것, 시그널(USR1·USR2)로 갱신·반납을 시키는 방식, 67/68 이 갈린 이유, lease 의 뜻, xid 가 무엇이고 TCP 에는 왜 없는지, dnsmasq 가 주소를 고르는 방식(MAC 해시 + 사전 ICMP).
23. **A5 관찰 — IPv6 는 링크 로컬이 있어야 DHCPv6 를 시작할 수 있다** — `ip addr flush` 가 링크 로컬까지 지워 dhclient -6 가 시작도 못 한 사고를 실습 편 함정으로. 05-01 §1 "클라이언트는 링크 로컬 주소를 쓴다"와 연결, IPv4 의 0.0.0.0 과 대조.

## 묶음 B 실습 중 (2026-09-23)

24. **[정정 필요] "dnsmasq 는 ICMP 뒤 3초쯤 기다린다"** — LAB.md·05-03 함정 셋째에 적었으나 B4a 캡처와 어긋남: .137 응답 0.3ms, .138 은 ping 뒤 0.2ms 에 OFFER. 3초는 클라이언트 재전송 간격. dnsmasq man page(또는 소스)로 사전 ping 의 대기 규칙과 DECLINE 된 주소를 얼마나 빼 두는지 확인한 뒤 두 곳을 고친다.
25. **두 확인의 분담을 "누가 알아듣나"로** — 학습자 질문 "REQUEST 로 이미 브로드캐스트했는데 왜 ACK 뒤에 또 확인하나". REQUEST 는 DHCP 서버만 알아듣고 수동 설정 장비는 DHCP 를 읽지 않는다, ARP 는 IP 를 가진 장비면 반드시 답한다, 침묵이 곧 "비어 있음". 05-01 two-checks 도식 옆에 한 문장.
26. **ARP 요청은 브로드캐스트·응답은 유니캐스트** — B4b 3·4번 eth.dst 차이를 학습자가 물음. 1장 결손(ARP 가 MAC 브로드캐스트)과 같은 뿌리.
27. **[학습자 요청] B5 릴레이 흐름도** — 라우터의 두 다리(eth1 seg-b·eth0 seg-a)에서 같은 DISCOVER 가 바뀌는 네 칸(eth.dst·ip.src·ip.dst·giaddr)을 "들어가기 전/나온 뒤"로 나란히. giaddr 로 서버가 범위를 고르는 분기까지. 05-01 relay-v4 도식과 겹치면 확장.
28. **giaddr 이 왜 클라이언트 쪽 다리 주소인가** — 학습자가 힌트 두 번에도 못 닿음. 서버가 giaddr 로 서브넷을 고른다 → 반대쪽 주소를 적으면 클라이언트가 이웃과 다른 서브넷 주소를 받는다는 인과 한 문단. relay.conf 두 인자의 역할(자기 수신 인터페이스·giaddr 값 / 넘길 서버)도.
29. **[학습자 요청] DNS 메시지 구조** — 헤더 플래그(qr·aa·rd·tc, rcode)와 네 칸(Question·Answer·Authority·Additional), OPT 가 Additional 에 실린다는 것. dig 출력 `flags:`·`QUERY/ANSWER/AUTHORITY/ADDITIONAL` 줄을 읽는 법. 05-02 §1~§2 또는 05-03 C2·C3.
30. **TC 는 실패가 아니다** — 학습자가 두 번 "실패"로 읽음. rcode 0 + TC=1 + answers 0 = "여기 못 담았으니 TCP 로 다시". NXDOMAIN(rcode 3)과 나란히.
31. **[AI 실수 재발 방지] 실습 편 tshark 명령은 빈 칸을 `-` 로 채운다** — C3 에서 `column -t` 열 밀림 재발(4장 look-tls.sh 에서 고친 것). 05-03 에 쓰는 모든 tshark 표 명령에 awk 채우기를 넣거나 look-dns.sh 를 만든다.
32. **[05-02 문장 점검] "성능을 잴 때는 재조립을 끈다"** — 원서 목적은 continuation 개수 세기. C5 실측: 끄면 http.time 이 첫 조각(첫 바이트) 기준 0.0442, 켜면 마지막 조각(마지막 바이트) 기준 0.0470. 다운로드 시간을 재려면 켜야 하고, 서버 처리(첫 바이트)는 끈 쪽. "무엇을 재느냐에 따라 갈린다"로 05-02 §3 문장과 치트시트·면접 대비를 고친다. 재조립을 켜도 조각 프레임은 목록에 남는다는 것도(학습자가 사라진다고 예측).
33. **CONNECT 터널 반대편 캡처** — 클라이언트↔프록시만 보면 IP 로 TLS 상대를 알 수 없다(학습자 지적). 프록시↔서버 쪽도 캡처해 같은 ClientHello 가 .21→.20 으로 건너가는 것을 05-03 C6 에 추가. TLS 1.3 이라 인증서도 암호화(opaque_type 23)라는 것, 4장 1.2 와 대조.
34. **[학습자 질문] 호스트별 라우팅 프록시 — TLS 종단 vs SNI 패스스루** — 05-02 CONNECT 절 끝이나 심화에 한 문단. TLS 의 "양 끝"이 어디냐가 방식에 따라 갈린다. gateway-lab 과 연결.
