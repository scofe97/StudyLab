## 독자

## 반영할 내용
11. HTTP 트랜잭션 정의 — 요청 하나와 응답 하나의 짝, 연결 하나에 여럿. 처음 쓰이는 자리보다 앞에.
12. http.time 이 재는 구간 — 연결 수립 왕복(네트워크 지연)과 요청→응답 간격(서버 처리 포함)의 차이. 연결 하나에 트랜잭션이 여럿이면 SYN 은 한 번뿐.
13. 세그먼트 개수가 무엇을 판단하게 해 주는가 — 위 18번 정정과 한 묶음.
14. 존 전송 정의를 §1 의 첫 등장 자리에.
15. DNS 가 TCP 로 넘어가는 조건 — 서로 다른 두 경우(응답 크기 · 존 전송)라는 것, EDNS(0) 가 바꾼 것은 첫째뿐이라는 것. "완화"라는 말 대신 무엇이 어떻게 달라지는지 동작으로 써.
16·19. CONNECT — 프록시 정의 한 문장, CONNECT 요청 한 줄에 무엇이 실리는지, 그 뒤 터널 안을 4장의 TLS 핸드셰이크가 그대로(ClientHello·SNI 평문) 지나간다는 것. 안 보이는 이유는 터널이 아니라 TLS. CONNECT 는 프록시에게, SNI 는 서버에게 하는 말.
17. 필터에 안 잡힐 때 — http 0줄(HTTPS 미복호화 · HTTP/2 · QUIC), dns 0줄(DoT · DoH).
20. DoT·DoH 를 왜 쓰는가 — 평문 DNS 는 UDP 든 TCP 든 읽히고 바뀔 수 있다, 전송과 암호화는 다른 축.

## 도식 — 적극적으로 추가해
흐름·순서·분기가 있는 자리마다 도식을 둬. 아래는 최소 목록이고, 쓰다가 흐름이 보이는 ### 가 더 있으면 더 그려.
- 이름 해석 실패 대 연결 실패 — 캡처에서 무엇이 보이고 무엇이 없는지로 가르는 분기
- CNAME 체인 — 질의 한 줄에 답 두 줄이 오고 이름이 이름을 거쳐 주소에 닿는 흐름(원문 예제 값 그대로)
- DNS 가 TCP 로 넘어가는 흐름 — UDP 질의 → 큰 응답 → TCP 재질의, EDNS(0) 로 UDP 에 머무는 갈래, 존 전송은 처음부터 TCP
- http.time 타임라인 — SYN·SYN/ACK·ACK 구간과 요청→응답 구간을 한 축에, 트랜잭션 둘이 한 연결에 실린 모습
- 재조립 켬·끔 — 같은 응답이 한 줄로 보일 때와 조각 수가 드러날 때
- CONNECT 터널 시퀀스 — 클라이언트·프록시·서버 세 줄. 평문 CONNECT → 200 → 터널 안의 ClientHello(평문·SNI) → 암호화 구간
- 필터에 안 잡힐 때 분기도 — http 0줄 · dns 0줄에서 각각 무엇을 확인하나
- 전송과 암호화 2×2 — UDP 53 · TCP 53 · DoT 853 · DoH 443 을 평문 대 암호화, 전용 포트 대 웹에 섞임으로
도식 규약: 그리기 전에 본문을 grep 해 본문이 지정한 내용과 맞추고, 문제를 먼저 놓고, 방향이 핵심이면 노드를 가로로 놓고, 수치는 흐름 안에 걸어. 도식이 담은 내용은 산문에서 걷어내. 기존 도식(dns-parts · dns-record-types · http-response-time · status-ranges)과 겹치면 새로 만들지 말고 확장해. SVG 는 Chrome 으로 렌더해 눈으로 확인하고 오버플로·겹침 센서를 돌려.
