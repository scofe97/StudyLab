# ssh-bbs 로드맵

이 문서는 SSH 로 들어오는 레트로 BBS `ssh-bbs` 를 키우는 순서표입니다. 2026-11-04 에 정했습니다. 단계마다 세부는 GitHub 이슈(#33~#44)에, 판단은 ADR 에 남깁니다. 구현은 npg 책 트랙 v0.13 이 끝난 뒤 시작합니다. npg 확장 트랙과의 순서는 그때 정합니다.



## 왜 SSH BBS 인가

> 접속 통로 하나(SSH)에 기능을 얹어 가며, 기능마다 그 밑의 네트워크 주제를 배웁니다.

SSH 는 대부분의 기기에 클라이언트가 이미 깔려 있습니다. 그래서 `ssh 닉@호스트` 한 줄이면 어디서든 별도 설치 없이 들어올 수 있습니다. 이것이 이 랩의 출발점입니다. 들어온 사람에게는 예전 PC 통신처럼 채팅방, 게시판, 자료실, 도어 게임을 보여 줍니다.

기능은 공부 주제를 끌어오는 미끼이기도 합니다. 채팅방을 만들면 느린 손님 문제를 풀어야 하고, 화면을 그리면 ANSI 제어 문자와 한글 폭을 다뤄야 합니다. 자료실은 SFTP 를, 포트 포워딩은 SSH 채널 구조를, 노드 간 연동은 복제와 중복 제거를 배우게 합니다.

SSH 서버는 `golang.org/x/crypto/ssh` 로 직접 짭니다. 채널·요청을 직접 다뤄야 S8 포트 포워딩의 구조가 보이기 때문입니다. 화면도 TUI 프레임워크 없이 ANSI escape 로 직접 그립니다. 그 밖의 영역은 Go 추천 목록(cobra·koanf·zerolog·sqlc·testify)을 씁니다.

```pseudocode
접속 기반    S1 SSH 서버 ─ S2 채팅방 ─ S3 터미널 화면 ─ S4 Telnet 입구
BBS 기능     S5 게시판 ─ S6 자료실 ─ S7 도어 게임
네트워크     S8 포트 포워딩 ─ S9 노드 간 연동
운영·공개    S10 남용 방지 ─ S11 관측 ─ S12 공개 배포
```



## 진행 규칙

> 단계마다 학습 문서로 배우고, 실습으로 판단하고, 원인을 숨긴 장애로 확인합니다.

이 랩에는 따라갈 책이 없습니다. 그래서 단계마다 학습 문서를 먼저 씁니다. 학습 문서는 `runners-high` 의 `write/02_os/project/ssh-bbs/` 에 두고, 진행 상태도 그 폴더의 README 에 둡니다. 근거 자료는 RFC 와 공식 문서 같은 원문입니다.

각 단계는 아래 순서로 돕니다. 실습 시작 관문은 그 단계 학습 문서의 Phase 1~2 통과입니다. Phase 4 자답 검증은 복습 회차에서 따로 하므로 실습을 막지 않습니다. 이 규칙은 npg 로드맵 「진행 규칙」과 같습니다.

1. 학습 문서 Phase 1~2
2. 이슈의 판단마다 ADR (`docs/adr/`, S1 에서 폴더를 만듭니다)
3. 구현과 시험 (코드는 학습자가 직접 입력합니다)
4. 장애 리허설 (`docs/rehearsals/`)
5. 태그 `ssh-bbs/v0.N.0` (S1 이 `v0.1.0`)

이슈마다 `## 선행 학습 (write/)` 절이 있습니다. 경로는 `runners-high` 저장소의 `write/` 아래 경로 문자열로 적습니다. 다른 저장소라 상대 링크가 깨지기 때문입니다. 다룬 문서가 없는 주제는 "write 없음 — 진입 시 학습 문서부터" 라고 적었습니다.

모든 이슈에는 `ssh-bbs` 라벨을 붙입니다. 마일스톤은 위 그림의 네 묶음입니다. 기한은 그 묶음에 들어갈 때 정합니다.



## 단계

> S1~S7 이 BBS 자체를 만들고, S8~S9 가 네트워크 기능을, S10~S12 가 공개 준비를 맡습니다.

| 단계 | 이슈 | 태그 | 기능 | 공부 주제 | 근거 원문 |
|---|---|---|---|---|---|
| S1 | #33 | v0.1.0 | SSH 서버 | 핸드셰이크, 호스트 키, 공개키 인증, PTY | RFC 4251~4254 |
| S2 | #34 | v0.2.0 | 채팅방 | 고루틴 허브, 브로드캐스트, 느린 손님 | Go 메모리 모델 |
| S3 | #35 | v0.3.0 | 터미널 화면 | ANSI escape, 줄 편집, 한글 2칸 폭 | ECMA-48, UAX #11 |
| S4 | #36 | v0.4.0 | Telnet 입구 | 옵션 협상, 전송과 세션 분리 | RFC 854·857·858·1073 |
| S5 | #37 | v0.5.0 | BBS 게시판 | sqlite, sqlc, 페이징, 쪽지 | sqlite 문서 |
| S6 | #38 | v0.6.0 | 자료실 | SFTP subsystem, 경로 가두기 | draft-ietf-secsh-filexfer-02 |
| S7 | #39 | v0.7.0 | 도어 게임 | 게임 루프, 틱, 상태 동기화 | — |
| S8 | #40 | v0.8.0 | 포트 포워딩 | direct-tcpip(-L), tcpip-forward(-R) | RFC 4254 §7 |
| S9 | #41 | v0.9.0 | 노드 간 연동 | 저장 후 전달, 중복 제거, 논리 시계 | FTSC 문서 |
| S10 | #42 | v0.10.0 | 남용 방지 | 속도 제한, 연결 상한, 실패 벌점 | OpenSSH sshd_config(5) |
| S11 | #43 | v0.11.0 | 관측 | 구조 로그, Prometheus 지표 | Prometheus 이름 규칙 |
| S12 | #44 | v0.12.0 | 공개 배포 | systemd, 호스트 키 보관, 백업 | systemd 문서 |

S4 Telnet 은 S3 의 화면 코드를 그대로 다른 전송에 붙여 보는 단계입니다. 그래서 S3 바로 뒤에 둡니다. 전송과 세션의 경계가 여기서 갈리므로 S6 SFTP 와 S8 포워딩도 같은 경계 위에 얹습니다.

S8 의 `-R` 리버스 터널은 npg 확장 트랙 X9(#18)와 같은 문제를 SSH 위에서 풉니다. 먼저 끝난 쪽의 ADR 과 리허설을 다른 쪽의 선행 학습으로 씁니다.

S9 노드 간 연동은 FidoNet 처럼 BBS 서버끼리 게시판을 주고받는 단계입니다. 완료 기준은 맥북 안 두 노드라서 공개 서버가 필요 없습니다.



## 공개 관문

> 맥북에서 먼저 만들고, 남용 방지와 관측을 갖춘 뒤에만 공인 서버에 올립니다.

S1~S11 은 모두 맥북 로컬에서 끝냅니다. S12 만 공인 서버를 쓰며, 실습은 맥북만 쓴다는 원칙의 예외입니다. 인증과 속도 제한 없이 SSH 서버를 인터넷에 열면 봇의 인증 시도가 곧바로 몰립니다. 그래서 S10·S11 이 끝나기 전에는 열지 않습니다.

공개 직전에는 아래를 확인합니다.

- S10 의 연결 상한과 실패 벌점이 켜져 있다
- S11 지표로 접속 수와 인증 실패를 볼 수 있다
- Telnet 입구가 꺼져 있다 (암호화가 없기 때문입니다)
- 포트 포워딩은 허용 목록 안에서만 열린다
- sqlite 와 자료실 백업을 복구해 보았다

호스트 키, 서버 주소, 토큰은 이 저장소에 넣지 않습니다.



## 참고 구현과 라이선스

> 참고 구현의 기능은 아이디어로만 가져오고 코드는 링크로만 봅니다.

| 구현 | 언어·라이선스 | 이 랩에서 |
|---|---|---|
| [c4punks/ssh-chatter](https://github.com/c4punks/ssh-chatter) | C, GPL-2.0 | 기능 목록(채팅방, `/bbs`, ANSI 아트, scp 자료실, FidoNet, Telnet)을 참고합니다. 코드는 보지 않고 README 만 참고합니다 |
| [gosuda/ssh-chat](https://github.com/gosuda/ssh-chat) | Go, 라이선스 표기 없음 | ssh-chatter 의 원본입니다. 라이선스가 없으므로 코드를 옮기지 않습니다 |

GPL 코드를 옮기면 이 저장소 전체가 같은 라이선스 조건을 따라야 할 수 있습니다. 라이선스가 없는 코드는 복제 권리가 없습니다. 그래서 두 구현 모두 링크로만 둡니다(AGENTS.md 「공개 저장소 규칙」).
