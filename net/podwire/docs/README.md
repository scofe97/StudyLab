# docs — Stage 노트

Stage 를 하나 끝낼 때마다 노트를 한 편 남긴다. 코드는 무엇을 했는지 보여 주지만
**무엇을 틀리게 예상했는지**는 남기지 않는데, 배우는 쪽은 대개 그쪽이다.

## 쓰는 순서

1. **예측** — 명령을 치기 전에 결과를 적는다. 틀려야 남는 게 있으므로 자신 있게 적는다
2. **실행** — 실제 출력을 붙인다. 요약하지 말고 그대로
3. **대조** — 예측과 어긋난 것을 먼저 쓴다. 맞은 것은 짧게

## 파일명

`XX-YY.제목.md` 에서 `XX` 는 Stage 번호, `YY` 는 그 Stage 안의 순번이다.

```
00-01.netns·veth 를 Go 로 짓기 — netlink 와 LockOSThread.md
01-01.CNI 플러그인 — kubelet 이 부르는 자리에 내 바이너리.md
01-02.VXLAN 오버레이 — 캡슐화가 MTU 를 갉아먹는다.md
02-01.kube-proxy 없이 Service — 확률 사다리가 코드가 된다.md
```

프론트매터는 `title`·`tags`·`status`·`updated` 를 둔다.
나중에 `runners-high/write/` 로 옮길 수 있게 규약을 미리 맞춰 두는 것이다.

## 빈 파일은 만들지 않는다

착수하지 않은 Stage 의 자리를 미리 파 두지 않는다. 빈 스텁이 쌓이면
목차만 그럴듯하고 안은 비어 있는 상태가 오래 간다. 쓸 내용이 생겼을 때 파일을 만든다.

도식은 `_assets/` 에 정적 SVG 로 둔다. Stage 1·6 의 흐름도만 예외로
`~/runners-high/project/flow-editor` 에서 만든다 — 거긴 빌드 파이프라인이 따로 있다.
