# JVM 옵션·실행 레퍼런스

실습마다 등장하는 `java`/`javac` 옵션을 한 곳에 모은다. 새 옵션을 만나면 "어디서 처음 썼는지(실습)" 와 "무엇을 위한 것인지" 를 함께 적어 누적한다. 옵션을 외우는 게 목적이 아니라, *왜 이 실습에 이 옵션이 필요했는지* 를 다시 떠올릴 수 있게 하는 게 목적이다.

## 옵션 문법 빠른 참고

`java` 옵션은 세 부류로 갈린다. 부류를 알면 처음 보는 옵션도 형태로 성격을 짐작할 수 있다.

| 형태 | 부류 | 뜻 | 예 |
|------|------|-----|-----|
| `-옵션` | 표준 옵션 | 모든 JVM이 보장, 잘 안 바뀜 | `-cp`, `-server`, `-version` |
| `-X옵션` | 비표준 옵션 | 벤더별, 다음 버전에 바뀔 수 있음 | `-Xmx`, `-Xms`, `-Xint` |
| `-XX:+옵션` / `-XX:-옵션` | 고급(실험) 옵션 | `+`는 켜기, `-`는 끄기. 튜닝·디버깅용 | `-XX:+PrintCompilation` |
| `-XX:옵션=값` | 고급(값 지정) 옵션 | 수치/문자열 값을 줌 | `-XX:MaxInlineSize=35` |

> `-XX:+/-` 의 `+`/`-` 를 헷갈리지 말 것. **`+`가 켜기, `-`가 끄기**다. `-XX:-TieredCompilation` 은 "TieredCompilation 을 끈다" 는 뜻이다.

## 컴파일·JIT 관련

JVM은 코드를 처음엔 **인터프리터**로 한 줄씩 느리게 실행하다가, 자주 도는 코드(hot spot)를 발견하면 **JIT 컴파일러**로 기계어로 바꿔 빠르게 만든다. JIT에는 두 단계가 있다.

- **C1 (client 컴파일러)**: 빠르게 컴파일하고 최적화는 가볍게 한다.
- **C2 (server 컴파일러)**: 느리게 컴파일하지만 최적화가 공격적이다. 루프 끌어올리기(hoist), 인라이닝, 죽은 코드 제거 등을 적극적으로 한다.

**Tiered Compilation**(계층형 컴파일, 기본 ON)은 C1 → C2로 점진적으로 단계를 올리는 기본 전략이다.

| 옵션 | 무엇을 하나 | 왜 실습에서 쓰나 | 처음 등장 |
|------|------------|-----------------|----------|
| `-XX:-TieredCompilation` | 계층형 컴파일을 끄고 **C2만** 쓰게 강제 | C2의 공격적 최적화(루프 hoist)를 강제해 **가시성 버그 재현율을 높인다**. 기본 설정으론 우연히 안 터질 수 있다 | ch12 visibility (`VisibilityBug`) |
| `-server` | 서버 모드 JVM 선택 (= C2 지향) | 위와 같은 목적. 64비트 JVM은 대개 기본이 server라 생략 가능 | ch12 visibility |
| `-Xint` | JIT를 끄고 **인터프리터만** 사용 | JIT 최적화를 배제하고 바이트코드 그대로의 동작을 볼 때 | (예정) |
| `-Xcomp` | 첫 호출부터 즉시 컴파일 | warm-up 없이 컴파일된 코드를 볼 때 | (예정) |
| `-XX:+PrintCompilation` | 어떤 메서드가 언제 JIT 컴파일됐는지 로그 출력 | hot spot이 실제로 컴파일되는 시점을 관찰 | (예정) |

### 가시성 버그 재현 (ch12 visibility) — 옵션이 필요했던 이유

```bash
java -XX:-TieredCompilation VisibilityBug
```

`volatile` 없는 `while (!stop)` 루프가 영영 안 멈추는 버그는, **C2가 루프를 끌어올려(hoist)** `stop` 을 다시 읽지 않게 최적화하기 때문에 가장 잘 드러난다. Tiered 컴파일이 켜져 있으면 C1 단계에 머물러 우연히 버그가 안 보일 수 있어서, `-XX:-TieredCompilation` 으로 C2를 강제해 재현율을 올린다. 같은 코드에 `volatile` 한 글자만 붙인 `VisibilityFixed` 는 이 옵션을 줘도 정상 종료한다 — 그 대조가 실습의 핵심이다.

## 클래스패스·실행 기본

| 옵션 | 무엇을 하나 | 처음 등장 |
|------|------------|----------|
| `-cp` / `-classpath` | 클래스·JAR 탐색 경로 지정 | classpath-basics |
| `-d <dir>` (javac) | 컴파일 결과 `.class` 출력 디렉토리 지정 (패키지 경로대로 생성) | classpath-basics |
| `-version` | JVM 버전 출력 | — |

## GC·메모리 관련

| 옵션 | 무엇을 하나 | 처음 등장 |
|------|------------|----------|
| `-Xmx<size>` | 최대 힙 크기 (예: `-Xmx512m`) | ch02 heap OOM |
| `-Xms<size>` | 초기 힙 크기 | ch02 |
| `-XX:+UseSerialGC` | Serial GC 선택 | ch03-gc |
| `-Xlog:gc*` | GC 로그 출력 (JDK 9+ 통합 로깅) | ch03-gc |

> GC 컬렉터별 옵션과 로그 위치 지정은 `tools/run-with-gc-log.sh` 래퍼를 참고. README "실행" 섹션에 사용법이 있다.

## 진단·역어셈블

| 도구/옵션 | 무엇을 하나 | 처음 등장 |
|----------|------------|----------|
| `javap -v <class>` | 클래스 파일 역어셈블 (바이트코드·상수풀·메이저 버전) | ch01, ch06 class-file |
| `javap -p -c <class>` | private 포함 + 바이트코드 본문 출력 | ch03 classloader |
| `jcmd <pid> GC.heap_dump` | 가동 중 JVM 힙 덤프 (`tools/dump-heap.sh` 래퍼) | ch04 troubleshooting |

> `.class` 의 major version 으로 컴파일된 JDK를 확인할 수 있다: **65 = Java 21**, 61 = Java 17, 52 = Java 8.

## 새 옵션 추가 규약

실습에서 처음 보는 옵션을 만나면:

1. 위 분류 표(컴파일·JIT / 클래스패스 / GC / 진단) 중 맞는 곳에 행을 추가한다.
2. "무엇을 하나" 는 한 문장, "왜 실습에서 쓰나" 는 *그 실습 맥락* 으로 적는다 (일반론 금지).
3. "처음 등장" 에 챕터·실습 이름을 박아 나중에 그 실습으로 되돌아갈 수 있게 한다.
4. 옵션 하나에 한 줄 — 길어지면 별도 ### 소제목으로 빼서 코드블록과 함께 설명한다.
