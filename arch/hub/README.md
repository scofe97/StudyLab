# hub-lab

두 외부 시스템 사이에서 요청을 옮기는 연동 허브를 단계별로 짓는 학습 랩입니다.

## 무엇을 확인하려는 랩인가

연동 허브는 한쪽 시스템(요청 원천)의 데이터를 읽어 다른 쪽 시스템(실행 대상)을 호출하고, 그 결과를 자기 저장소에 남깁니다. 기능은 단순해 보이지만 실패는 경계에서 납니다. 외부 시스템의 모델이 코어로 새어 들어오고, 데이터소스가 여럿이면 트랜잭션이 엉뚱한 DB를 지키고, 외부 호출과 DB 쓰기가 어긋나고, 서버가 두 대면 배치가 두 번 돕니다.

이 랩은 그 실패를 하나씩 직접 재현한 뒤 표준 해법으로 고칩니다. 업무 도메인은 다루지 않고, 경계 설계·연동·트랜잭션·동시성만 봅니다.

## 구성

| 모듈 | 역할 | 포트 |
|---|---|---|
| `hub-app` | 학습 대상인 연동 허브 | 8180 |
| `fake-target` | 가짜 실행 대상. 지연과 실패를 설정으로 주입 | 8190 |
| `compose.yaml` | 로컬 PostgreSQL (허브 저장소와 요청 원천 스키마) | 15432 |

## 스택

| 항목 | 값 |
|---|---|
| Java | 25 (Gradle toolchain) |
| Spring Boot | 4.1.1 |
| 외부 호출 | RestClient, HTTP 인터페이스 |
| DB | PostgreSQL 17 (Docker Compose), 테스트는 Testcontainers |
| 빌드 | Gradle 9.1 (래퍼) |

## Phase

각 Phase는 빌드·테스트·이해 확인 세 항목이 다 채워져야 완료입니다.

| Phase | 주제 | 재현하고 고치는 것 | 상태 |
|---|---|---|---|
| 1 | 포트와 어댑터 | 외부 모델이 코어에 새는 구조 → 질문 단위 포트와 교체 가능한 어댑터 | 뼈대 완료, 구현 전 |
| 2 | 외부 API 클라이언트 | 흩어진 헤더·오류 처리 → 인터셉터, 오류 분류, 타임아웃, 계약 테스트 | |
| 3 | 다중 데이터소스와 트랜잭션 | 트랜잭션 시작 시점에 고정되는 연결 → 데이터소스별 명시 분리 | |
| 4 | 쓰기 정합성 | 외부 호출과 DB 쓰기의 불일치 → Outbox와 멱등키 | |
| 5 | 스케줄러와 분산 락 | 인스턴스 두 개의 중복 실행 → DB 기반 락 | |
| 6 | 설정 기반 정책 | 코드에 박힌 규칙 값 → 설정 주입과 프로파일 | |
| 7 | 인증 위임 | 사용자 토큰의 노출과 대리 사용 → 서비스 간 토큰 전달 | |
| 선택 | 게이트웨이 연동, WAR·오프라인 빌드 | 앞단 게이트웨이 경유, 외부 WAS 배포 | |

## 실행

```bash
./gradlew build                         # 컴파일 + 테스트
./gradlew :hub-app:bootRun              # 허브 기동
./gradlew :fake-target:bootRun          # 가짜 실행 대상 기동
docker compose up -d                    # PostgreSQL (Phase 1부터)
```
