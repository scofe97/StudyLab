# 09-03 보강 메모 (학습 세션 중 수집 — 나중에 문서 반영 검토)

> 2026-07-15 학습 4-Phase 재현 세션에서 나온 보강 후보. 09-03 문서 본문은 학습 중 미수정 원칙이라, 여기 모아두고 세션 후 사용자 승인받아 반영.

## 1. 심링크 2단 원자성 — 시각화 + 리눅스 개념 보강

- **왜 2단인가**를 명시적으로: 1단(파일마다 심링크 직접 교체)이면 파일 여러 개일 때 "새 app.conf + 옛 db.conf" 섞인 찰나가 생겨 원자성 깨짐. 2단은 교체 지점을 `..data` 하나로 모아 전부 동시 교체.
- **subPath = 0단**(심링크 아예 없음)임을 구분. "1단"과 헷갈리기 쉬움. subPath 파일은 읽히긴 하지만(읽기 O) ConfigMap 수정이 안 따라옴(갱신 X) — 심링크 체인을 우회하기 때문.
- Phase 3 실측 증거: patch 후 `app.conf` 심링크 타임스탬프는 안 바뀌고(04:14 유지) `..data`만 바뀜(04:19). = 개별 파일 심링크는 안 건드리고 `..data`만 튼다는 물증.
- 시각화 흐름 제안: (갱신 전) app.conf→..data→폴더A / (갱신 중) 폴더B 옆에 생성 / (갱신 후) ..data 화살표만 B로 틀기 — 3컷 SVG 또는 Mermaid.

## 2. 리눅스 권한·소유권 개념 보강 (fsGroup 이해 전제)

- 권한 체크는 계급이 아니라 **매칭**: 소유자→그룹→기타(others) 순으로 딱 한 칸만 적용.
- **주 그룹(gid) vs 보충 그룹(groups)**: 한 유저가 여러 그룹 동시 소속 가능. fsGroup은 프로세스를 해당 gid의 *보충 그룹 멤버*로 넣어 그룹 매칭을 성립시킴. Phase 3 실측: `groups=1000` → `groups=1000,2000`.
- **root = uid/gid 0** (1 아님).
- runAsUser/Group(프로세스 신분) vs fsGroup(파일 그룹 소유권) 방향 구분. fsGroup은 그룹 소유권만 바꾸고 사용자 소유권은 못 바꿈(§4 L235와 정합) — 실측: `root root` → `root 2000`.
